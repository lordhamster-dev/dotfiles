# 日期与时区细则

涉及日期解析、时间计算、时区转换、时间戳、日期查询范围或时间存储时，在实现前读取。

## 类型与时区边界

- 优先使用 `arrow` 处理输入输出边界的解析、格式化、时区转换与相对时间计算；已有标准库实现清晰可靠时，不为统一选型而替换。
- 仅表达日历日期时使用标准库 `date`；表达事件瞬间时使用 aware `datetime` 或 Pydantic `AwareDatetime`。领域模型优先使用标准类型，避免与日期工具库不必要地耦合。
- 业务日期和日界线从明确配置的时区计算，不依赖宿主机时区。按业务选择 UTC 或具体地区时区，不预设所有项目都使用同一时区。
- 不使用 naive 的 `datetime.now()`、`datetime.fromtimestamp()` 或 `date.today()` 推断业务日期。使用 `datetime.now(tz=...)`、`datetime.fromtimestamp(value, tz=...)` 等明确时区的入口。
- 保留外部输入的显式 offset / `Z`，通过 `.to(...)` / `.astimezone(...)` 转换；禁止对已带时区的值用 `tzinfo=` 或 `.replace(tzinfo=...)` 重新贴标签。
- 来源未定义时区时，拒绝有歧义的 naive 事件时间；只有明确来源时区契约后，才能赋予该时区。

## 精度、区间与历史日期

- 明确时间戳是整数秒、小数秒、毫秒还是整数微秒，字段命名不能代替契约；精度敏感路径避免 `.int_timestamp` 或其他截断操作。
- 按日期查询事件使用半开区间 `[首日零点, 末日次日零点)`，端点在业务时区构造，再按存储契约转换；不用 `23:59:59` 上界或相邻闭区间。
- 截止时点查询 `timestamp <= cutoff` 是合法的 as-of 语义，不应机械改成半开区间。
- 历史输入缺少年月日时，从请求的历史日期与来源规则推导，不使用当前年份补全。
- 工作日、节假日、周期等日历规则由业务定义，不将通用日期库的日期运算等同于业务日历。

## 边界与性能

- 日期计算覆盖月末、闰年和跨年；涉及周期规则时先明确语义，不以库的默认行为替代业务约定。
- 避免循环内重复计算不变值或反复转换类型；不可变派生值可缓存，可变对象缓存必须有失效机制。
- 时间逻辑渐进修改，验证 UTC 宿主、业务时区午夜、月末与年末、显式 offset 和亚秒精度；相关时区涉及夏令时时补充转换边界测试。
